# Unity 全面迁移：官方对照与实施依据

核查日期：2026-09-07。用途：指导《青云问道》全面手游客户端迁移；本文件不是“已完成高还原”的验收声明。所有素材只用于研究，未复制到 Assets。现有后端机制优先原样接通；文中的产品建议不授权自行增加官方数值或重做后端。

## 证据等级与版本边界

- **官方明确说明**：雷霆《一念逍遥》官网正文公开的功能、入口、条件。
- **官方图像观察**：实际打开官网内嵌原图；GIF抽查起始、中间、末尾帧。可以证明画面元素及片段内变化，不能推出完整客户端动效周期。
- **本项目取舍**：根据已授权的平面水墨、圆球头像和全面迁移目标提出的实现建议，不是原作机制。
- **待核实**：未找到足够可靠的官方画面或规则，保留现有游戏规则并明确项目差异，不宣称一比一。

2020年资料代表公测前人界版本；2023年修炼室文章明确标注“开发中”；2024–2026年公告用于识别后续变更，不能把多个年份拼成一个当前实机版本。2026-06-22官方[血修版本预告](https://xian.leiting.com/news/858.html)已介绍血炼方向；全面迁移范围不应被表述为复刻2026官方所有修炼方向。

## 第一优先：六导航与场景式洞府

**图像观察，2020-12**：[洞府实机原图](https://xian.leiting.com/static/upload/editor/20201209/160750624936586479146551.jpg)，来自[洞府玩法](https://xian.leiting.com/news/3.html)（2020-12-03）。

- 竖屏底部六个墨色圆形入口依次为：人物、秘境、城镇、宗门、洞府、行囊。不是五导航，也不是每个系统平铺一张大卡。
- 顶部窄栏承载境界进度及货币，图中央保留大幅浅色山水；下部聊天预览贴在背景上，右侧有展开气泡。
- 聚灵阵、造化至宝、化身、灵兽、丹房、器室、药园，以圆印单字和短标签落在山体、楼阁、池畔相应位置；修法中的小人和青色灵气圈是场景焦点。
- **官方明确说明**：洞府承载修炼、种植、炼丹、炼器、御兽，聚灵阵升级提高基础灵气与修炼效率。丹房生产含提升修为、属性、突破率的丹药。[正文](https://xian.leiting.com/news/3.html)

**本项目取舍**：先完成六个稳定一级目的地；洞府内每个已有功能对应可点击建筑印记。未迁移的功能不能放置貌似可用但无反馈的按钮。原创山水负责空间层次，透明点击区域负责建筑入口，资源栏和返回始终易读。宽屏扩大画境留白而非把所有功能变成横向仪表盘。圆球头像用于战场，修炼室可以使用项目已有原创打坐人物，不能误把“圆球战斗”扩成所有界面只准用球。

**验收流程**：洞府→聚灵阵详情→升级→真实消耗与修炼效率更新→返回；洞府→丹房/器室/药园→对应真实制作或种植流程→行囊看结果。不得只验证入口可点。

## 人物、功法、神通和行囊

**官方明确说明**：2024-02-01[公告](https://xian.leiting.com/news/447.html)给出“人物→神通→右下秘术”入口；神通学习有境界要求；顶部境界从固定体法改为当前/辅修方向。这证明人物养成与战斗场景是独立目的地，不能把2020固定双修条当成当前全量界面。

2025-03-28[公告](https://xian.leiting.com/news/670.html)说明功法属性页应完整展示每层效果，道具弹窗显示拥有数量，功法相关道具显示养成进度；新增装备锻造时自动转器灵以减少占用行囊。2022-10-28[公告](https://xian.leiting.com/news/237.html)提及可在道具展示页设置部分道具红点。

**图像缺口**：本次未得到可独立核实的完整官方人物、功法树、神通装配、行囊装备详情实机，不能指定其“官方精确槽位数、布局、拖动方式”。灵兽页卡片网格不能冒充装备背包证据。

**本项目取舍**：人物页呈现头像/原创立绘、境界、战力、属性；子入口接现有功法、神通、装备。行囊使用清楚的分类、数量与品质边框，点选后展示已有属性、穿戴条件、当前装备比较、实际可执行操作。功法详情展示已学/下级效果与消耗；神通显示已学、可学、受限条件，并连接后端实际装配逻辑。以上是面向迁移的项目设计，尚无官方精确视觉还原结论。

**验收流程**：学习功法或神通→资源减少与等级刷新→退出重进仍一致；行囊→装备详情→穿戴/卸下→人物属性更新→战斗使用该状态；材料不足、未达境界、空背包均可理解。

## 法宝、古宝与寻宝：不得混成一个抽奖页

**官方证据**：2020年[洞府器室原图](https://xian.leiting.com/static/upload/editor/20201203/160698858636586479141018.jpg)表现居中炉具、品质信息、材料与锻造按钮；这是装备制作表现。2023-08-25[公告](https://xian.leiting.com/news/349.html)明确古宝存在可升星分页与可合成分组。2022-08-19更新[宗门寻宝说明](https://xian.leiting.com/news/218.html)明确宝图碎片→分享或解锁→到指定秘境宝藏点挖宝→奖励/事件；这与概率抽古宝是不同玩法。

**本项目取舍**：法宝页处理现有穿戴/养成，古宝页处理已有收集/升星/套装，寻宝页处理本项目已实现的抽取、消耗和奖励；如果项目寻宝是抽卡，应明确为项目玩法，不称复刻官方宗门寻宝。奖励必须来自服务端结果，不预先用客户端动效决定。

**缺口**：常驻古宝抽取概率、保底、抽取货币、动画、法宝全部装备槽与强化公式本次未确认，不得填入“官方同款”。

**本项目取舍**：原创城镇场景+NPC或建筑入口；商店保留商品行而非满屏大卡；选商品→数量/价格→购买结果→库存与余额更新。任务支持可领、进行中、可交付及已完成状态，并能抵达相应目的地。榜单需有类别、本人名次、数据更新时间与真实排行条目。论剑台/跨界论道是战斗玩法，不等同于只展示战力榜。

## 当前原型与完整手游的关键差距

本次只读检查 `Assets/Scripts/Bootstrap.cs` 的 `OnGUI()`：当前主要是入山、自己信息、Boss信息、战果以及跟随修士/前往山巅/撤回山门。圆球头像平面战斗符合已确认方向，但它只能证明秘境战场表现，并未覆盖完整手游体验。

| 差距 | 应实施的最小完整结果 | 真实验收 |
| --- | --- | --- |
| 场景导航 | 六个稳定一级目的地及返回层级 | 任意页面可返回并保留合理状态 |
| 养成闭环 | 洞府/修炼/突破/制作/人物属性 | 操作造成持久化数值变化 |
| 物品闭环 | 掉落→行囊→详情→使用/装备→属性/战斗 | 重登及战斗结果一致 |
| 城镇闭环 | NPC/任务/商店/榜单 | 对话与购买/交付真实生效 |
| 多人闭环 | 组队→进入→结束→奖励；好友/聊天 | 两个独立玩家确认相同事实 |
| 移动端构图 | 水墨画境、薄资源栏、六导航、局部灵气焦点 | 竖屏实际运行，无字溢出/重叠/误触 |
| 接口错误与加载 | 明确等待/失败/空态/重试 | 断网、鉴权失败、余额不足可理解且不假成功 |

原则：先迁移真实流程与页面层级，再提升原创美术；不要用截图式假按钮或Web页面嵌入冒充Unity全面迁移。官方资料能指导设计方向，只有上述实际流程与视觉验收完成后，才可报告相应模块已经完成。

### 必要偏差与优先顺序

**P1-1：世界页缺少持续可见的自身/锁定目标战斗状态。** 入境截图中，自身与目标仅靠圆圈、相邻站位和一条法术线联系；顶部面板显示累计战果，未显示两者姓名及当前气血。只读代码核实 `WorldView.cs` 将血条限制为非满血时显示，所以这不是简单把截图中“看不到血条”误判成完全没有实现。[2023-12-08官方公告](https://xian.leiting.com/news/412.html)明确在切磋及其列举的多人玩法增加双方头像、气血、真元和状态，部分玩法关注自身与锁定目标；它没有证明所有2026秘境都采用相同布局。**本项目建议**：为自己和锁定目标保留薄状态区，先用已返回的真实气血比例与身份；没有真元字段就不填。满血也应看得出两方状态，避免用累计掉落替代战斗可读性。优先于增加装饰性法术。
