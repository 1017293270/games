## 0. 产品定位

自部署的多人放置修仙游戏。玩家离线也在修炼，上线处理突破、探索、组队副本、论道 PK、
围攻机器人。世界里常驻约 200 个 AI 修士（机器人），它们用**和玩家完全相同的公式**修炼、
升级、突破、参战，因此排行榜是活的，后台可随时调参。

- 平台：安卓浏览器优先（PWA），桌面同一套 UI。
- 画风：水墨（宣纸 `#F3EBDC`／墨 `#1E1B18`／朱砂 `#B23A2E`／青黛 `#3B5F6B`／金 `#C9A063`）。
- 联机：好友组队、共同下副本、互相 PK、组队围攻机器人。
- 部署：单机 Node 进程 + SQLite 文件，邀请码注册，后台可调全部数值。

## 1. 境界体系

9 个大境界 × 4 个小境界（前期／中期／后期／圆满）= **36 阶**，全局用扁平的
`stageIndex ∈ [0, 35]` 寻址。显示名形如 `金丹·前期`。

练气 → 筑基 → 金丹 → 元婴 → 化神 → 炼虚 → 合体 → 大乘 → 渡劫

### 1.1 节奏模型

单阶时长（凡灵根、无功法、无丹药、世界倍率 1）：

```
durationSec(realm, sub) = REALM_BASE_SEC[realm] × SUB_DURATION_MULT[sub]
SUB_DURATION_MULT = [1, 1.4, 1.8, 2.2]        // 前期/中期/后期/圆满，和 6.4
REALM_BASE_SEC    = [180, 1500, 9000, 36000, 64800, 116640, 209940, 377880, 680160]
```

`REALM_BASE_SEC` 前四项直接钉在派遣令给的时长带上；**化神起每境界 = 前一境界 × 1.8**
（取 1.5–2 带的中位偏上，整分钟取整）。

修为数字与速率只是**展示层**，不影响节奏：

```
baseRatePerSec(realm, sub) = REALM_RATE[realm] × SUB_RATE_MULT[sub]
REALM_RATE    = [1, 2, 4, 8, 16, 32, 64, 128, 256]   // 每大境界翻倍
SUB_RATE_MULT = [1, 1.1, 1.2, 1.3]
expRequired   = round(durationSec × baseRatePerSec)
```

于是 `expRequired / baseRatePerSec` 恒等于目标时长（测试断言这一点），
而顶阶修为落在 ~4.98 亿——修仙味够足，又远在 `Number.MAX_SAFE_INTEGER` 之内。

## 2. 修炼与懒结算

### 2.1 速率公式

```
rate = baseRate(stage)
     × 灵根品质          (凡 1.0 / 异 1.3 / 天 1.8)
     × (1 + 功法加成)
     × (1 + 丹药 buff)
     × world.cultivationMultiplier
     × 机器人系数         (玩家恒为 1；机器人 = talent × (1 + insight))
```

### 2.2 懒结算 `settleCultivation(char, nowMs, world)`

**没有任何定时器。** 修为是墙钟的纯函数：服务端每次碰到角色就补算
`lastSettledAt → now` 这段窗口。

规则：

1. **离线上限**：超过 `world.offlineCapHours`（默认 12 时）的时间**直接作废**，不入账。
   被作废的是窗口的**前半段**，所以在作废段里过期的丹药 buff 正确地已经失效。
2. **分段积分**：窗口按每个落在其中的 buff 过期时刻切段，每段内速率恒定，逐段精确积分；
   段内再按「填满当前阶」切分，因为跨阶时 `baseRate` 会变。
3. **小境界自动升**：前期 → 中期 → 后期 → 圆满 自动推进，无需操作、不会失败。
4. **圆满驻留**：到 `圆满` 后修为封顶在 `expRequired`，**不自动跨大境界**，
   多出来的时间计入 `wastedSec` 丢弃（不存银行）。这是催促玩家上线突破的核心钩子。
5. **纯函数**：返回新的 `CharacterState`，绝不修改入参。

返回 `{ character, gainedExp, elapsedSec, creditedSec, forfeitedSec, stageUps, atPerfection, wastedSec }`，
够客户端渲染「闭关归来」结算面板。

浮点容差 `SETTLE_EPSILON_SEC = 1e-6`：时间戳是 epoch 毫秒，double 在 1.7e12 量级上
往返一次约有 1e-7 秒误差，一微秒的松弛保证「正好修炼满一阶的时长」确实会升阶。

## 3. 突破

小境界自动升且必成。只有 **圆满 → 下一大境界** 需要显式突破，且会失败。

```
成功率 = min(0.95, (基础率 + 0.15 × 破境丹数) × world.breakthroughChanceMultiplier)
```

| 起始阶 | 目标 | 基础成功率 |
|---|---|---:|
| 练气·圆满 (3) | 筑基 | 80% |
| 筑基·圆满 (7) | 金丹 | 74% |
| 金丹·圆满 (11) | 元婴 | 67% |
| 元婴·圆满 (15) | 化神 | 61% |
| 化神·圆满 (19) | 炼虚 | 54% |
| 炼虚·圆满 (23) | 合体 | 48% |
| 合体·圆满 (27) | 大乘 | 41% |
| 大乘·圆满 (31) | 渡劫 | 35% |

- 每颗**破境丹** +15 个百分点，单次最多 4 颗，总上限 **95%**（永远留 5% 的敬畏）。
- **失败**：扣当前阶 `expRequired` 的 **20%** 修为，停留原阶，可再试。
- **渡劫**（大乘·圆满 → 渡劫·前期）额外要求先赢一场**天劫战斗**：
  对手是 `tribulationAvatar()` 生成的「天劫化身」（boss 档位属性，四个三层神通，无掉落）。
  服务端先跑战斗，赢了才允许掷突破。

`breakthroughChance(stageIndex, pills)` 对非圆满阶返回 `1`（小境界必成），
对 `stageIndex === 35` 返回 `0`（已至顶）。

## 4. 灵根与属性

### 4.1 灵根

五行（金木水火土，均匀随机）× 品质（凡 70% / 异 25% / 天 5%）。
品质给修炼速率乘数 1.0 / 1.3 / 1.8；五行决定同属性神通的亲和。
显示形如 `天灵根·火`。

### 4.2 八项属性

气血 hp · 攻击 atk · 防御 def · 速度 spd · 暴击 crit · 抗暴 critResist · 命中 acc · 闪避 eva。
前四项是绝对值，后四项是 [0,1] 的比率，战斗中与对手的对应项相减。

境界基线：

```
hp  = 120 × 境界系数 × 小境界系数        境界系数 = [1, 2.2, 4.8, 10.5, 23, 50, 110, 240, 520]
atk =  18 × …                            小境界系数 = [1, 1.15, 1.32, 1.52]
def =  10 × …
spd =  10 × (1 + 0.02 × stageIndex)      // 速度增长慢，保证出手序可读
crit       = 0.05  + 0.002  × stageIndex   （0.05 → 0.12）
critResist = 0.02  + 0.0015 × stageIndex   （0.02 → 0.073）
acc        = 0.90  + 0.002  × stageIndex   （0.90 → 0.97）
eva        = 0.03  + 0.001  × stageIndex   （0.03 → 0.065）
```

命中恒高于闪避 0.7 以上，所以战斗不会退化成互相 miss。

### 4.3 `computeStats`

```
最终值 = 基线 × (1 + Σ百分比加成) + Σ固定加成
```

百分比来源：装备 `percent × 品阶系数`、功法 `percent`、丹药临时 buff。
**同类相加、不连乘**——玩家能心算「剑 +12%、功法 +15% = +27%」。
固定加成最后落，让低阶装备在早期依然有感。

品阶系数：凡 1.0 / 灵 1.6 / 仙 2.6 / 圣 4.2。

### 4.4 战力 `powerScore`

```
攻 = atk × (1 + crit × 0.8 + acc × 0.2)
守 = def × 1.4 + hp × 0.22
速 = spd × 4 + (eva + critResist) × 60
战力 = round(攻 × 3 + 守 + 速)
```

攻方权重 3 倍，但守与速仍有份量，避免榜单被纯输出流垄断。用于排行榜、论道匹配、
以及战斗前的「能不能打」提示。

## 5. 战斗引擎

`simulateBattle(input): BattleResult`，**完全确定性**：同 seed 同输入 → 逐字节相同的
`log`。服务端算一次、存下来，客户端只做回放，绝不重掷。PRNG 是 mulberry32（32 位状态，
种子先过一轮 mix，保证相邻 seed 迅速发散）。

### 5.1 回合结构

```
round_start（按当前有效速度降序排出手序，同速则 A 队优先、再按队内位次）
  每个存活单位依次行动：
    灵力 +15（上限 100）
    从轮转指针开始扫 4 个神通槽，取第一个「冷却好 且 灵力够」的释放，指针推到它之后
    一个都不满足 → 普攻（系数 1.0，指针不动）
  回合末：所有冷却 -1，所有增益/减益持续回合 -1，归零则移除
```

- 起始灵力 100，每回合回 15。一层神通 11–15 点（可持续），三层 42–50 点（约 3 回合一次）。
- 默认 `maxRounds = 30`。
- 目标选择：伤害/减益 → **存活敌人中气血最低者**（集火），治疗/增益 → 自身或最重伤的队友。
  确定性：同气血按队内位次打破平局。

### 5.2 伤害公式

```
命中率 = clamp(命中 − 闪避, 0.35, 0.99)          未命中 → damage 事件 amount 0, dodged true
暴击率 = clamp(暴击 − 抗暴, 0, 0.95)             暴击 ×1.5
基础   = atk² / (atk + def)
伤害   = round(基础 × 技能系数 × 暴击 × 浮动)     浮动 ∈ [0.9, 1.1]，最低 1
```

`atk²/(atk+def)` 让防御是**减益递减**而非硬门槛：防御翻倍不会让伤害归零，
但堆防依然显著。同阶单挑约 8–12 回合结束，稳在 30 回合上限内。

### 5.3 结束判定

- 一方全灭 → `reason: 'team_wiped'`，胜者是活着的一方。
- 打满 `maxRounds` → `reason: 'max_rounds'`，**按剩余气血占比判胜**（各队 `Σhp / Σmaxhp`），
  完全相等才是 `draw`。这样论道不会陷入无意义的平局。

### 5.4 事件类型

`round_start | skill_cast | damage | heal | buff | debuff | death | battle_end`（判别联合）。
`damage` 带 `crit` / `dodged` 标记与命中后的 `targetHp`，客户端据此播飘字与血条。
`BattleResult` 还带 `finalHp`、`damageDealt`（伤害榜）、`seed`（可从结果反推回放）。

### 5.5 围攻血池

`Combatant.hp` 可覆盖初始气血：大于 `stats.hp` 时同时抬高上限（机器人共享血池），
小于时表示带伤参战（PvP 输了不满血）。组队围攻就是 4 打 1、目标血池巨大、
多波攻击累计扣血，打空才算击破。

### 5.6 大地图上的「一次出手」

战斗大地图（§8.1）不是回合制，但用的是**同一套数值**：`combat/damage.ts` 的
`effectiveStat` / `rollDamage` 从本节的公式里抽出来，回合制引擎与地图模拟共同调用，
掷骰顺序（命中 → 暴击 → 浮动）一字不改。

地图上的一次**出手**就等于回合制里的一个**回合**：灵力 +15、四个神通槽轮转一格、
所有冷却 −1。区别只在「什么时候轮到你」——回合制按速度排序，地图按出手时钟：

```
出手间隔 = 1200ms × clamp(1 − (速度 − 10) / 200, 0.6, 1.4)
```

所以速度在两种战斗里都是「出手更频繁」，含义一致；技能平衡不需要为地图重调一遍。

## 6. 神通与功法

### 6.1 神通（15 个，五行 × 三层）

角色有 **4 个神通槽**，按序轮转释放。

| 五行 | 一层 | 二层 | 三层 |
|---|---|---|---|
| 金 | 金锋斩（伤害 1.35 / 12 灵力） | 万剑归宗（群伤 0.95 / 30 / CD2） | 太白剑域（减防 30% + 伤害 1.8 / 45 / CD3） |
| 木 | 木灵愈体（治疗 1.6 / 15 / CD1） | 缠藤缚（减速 35% + 伤害 0.7 / 22 / CD2） | 青木回春诀（大治疗 3.4 / 42 / CD3） |
| 水 | 寒水诀（伤害 1.3 / 11） | 玄冰封（减速减攻 + 伤害 1.15 / 26 / CD2） | 沧澜怒涛（伤害 3.6 / 48 / CD3） |
| 火 | 烈焰掌（伤害 1.45 / 14） | 焚天符（减防减抗暴 + 伤害 1.5 / 28 / CD2） | 三昧真火（群伤 2.1 / 50 / CD3） |
| 土 | 磐石身（自增防 40% / 13 / CD2） | 大地之力（自增攻 35% 暴击 6% / 24 / CD2） | 山河镇魂（伤害 2.9 / 44 / CD3） |

解锁阶：一层 0、二层 6（筑基·后期）、三层 14（元婴·后期）。
新角色开局自动获得 4 个一层神通，本命五行排在轮转首位。

设计意图：一层撑输出下限，二层带控场/破防的「附加值」，三层是需要攒灵力的爆发。
四槽轮转让配装有取舍——全上三层会灵力枯竭退化成普攻。

### 6.2 功法（6 部，被动）

| 功法 | 品阶 | 修炼加成 | 属性 | 解锁 | 学费 |
|---|---|---:|---|---:|---:|
| 青云诀 | 凡 | +10% | 全属性 +5% | 0 | 0（开局赠） |
| 吐纳养气篇 | 凡 | +25% | 气血 +8% | 2 | 300 |
| 烈阳焚天功 | 灵 | +18% | 攻 +22% 暴 +3%，**防 −5%** | 6 | 1,500 |
| 玄冰真解 | 灵 | +18% | 血 +18% 防 +16% 抗暴 +3% | 6 | 1,500 |
| 五行归元诀 | 仙 | +40% | 血攻防 +20% 速 +8% | 14 | 9,000 |
| 太上忘情录 | 圣 | +75% | 血 +30% 攻 +30% 防 +25% 速 +15% | 24 | 60,000 |

`吐纳养气篇` 修炼快但几乎不涨战力，`烈阳焚天功` 修炼慢些却攻高防低——
让「修炼速度 vs 战力」成为真实取舍，而不是单调升级。

## 7. 装备与道具（30 件，一一对应 `docs/ASSETS.md` 的 `item/`）

四槽位：**法宝 / 法衣 / 饰品 / 灵宠**。品阶 凡／灵／仙／圣。

性格不同的玩家会做不同选择，机器人按 `botWeight` 自动抉择。

**秘境副本**（4 个，各 1 BOSS，2 波小怪 + BOSS）：

|---|---:|---|---:|
| 青云秘境 | 4 | 青云虎王 | 2 人 |

| 昆仑秘境 | 16 | 昆仑天兽 | 4 人 |

每日 3 次（`world.dungeonDailyLimit`）。BOSS 气血是同阶妖兽的 4 倍档位，
攻 1.35 倍——单人硬啃很难，组队是正解，这是把「联机」变成刚需的主要设计。

**怪物奖励**用「离线时长」表达而非拍脑袋：

```
妖兽修为 = baseRate(该阶) × 90 秒      // 一次击杀 = 1.5 分钟挂机
BOSS修为 = baseRate(该阶) × 1200 秒    // 一次击杀 = 20 分钟挂机
```

这样活跃玩家约等于 3 倍挂机效率——有奖励但不至于逼人肝，且**在任何境界都成立**，
不用逐阶手调。

### 8.1 战斗大地图

上面四张探索地图各有一张**俯视战场**（`content/zones.ts`，`zone.id === ExploreMap.id`，
名字与解锁阶都从地图取）：60×90 格，入口在南侧，越往北的妖兽越硬——难度曲线就是走多远，
没有隐形墙。服务端为每张图跑一个持续模拟（`zone/sim.ts` 是纯函数核心，客户端 mock 共用同一份）。

图里四种实体：**玩家**、**机器人**（都是头像球 + 境界色环 + 道号 + 血条）、
按刷新点复活的**妖兽**、每 `bossIntervalMinutes` 现身一次的**BOSS**（一图一只，
前 5 名伤害者各掷一次掉落）。

修士全自动：找最近的妖兽 → 走过去 → 进射程后按出手时钟出手（§5.6）。
玩家只做三件事：选图、撤离、看战果。倒下后 `mapDeathRespawnSec` 秒回入口满血复活，
并获 60 秒免修士攻击。

**各打各的怪。** 目标每 2 秒重选一次，但**已经在打的妖兽不撒手**——只要它还活着、
还在视野（`ZONE_SEEK_RADIUS` 14 格）内，重选就跳过这一位（`stickyTarget`）。
挑新目标时，**别人锁定并已经打过的妖兽加两倍视野的距离罚分**，被两名以上修士盯上的
再加半个视野；于是「无主的那只」几乎总是赢，一群修士自然摊开。
**罚分只在视野内部比大小**——视野里还有活着的妖兽，就绝不会因为它被占而跑到视野外去，
14 格内一只不剩才全图找最近的那只。只有两件事能拽走
一个正在打怪的修士：被别的修士打了（照旧反击），以及 BOSS 的号召。
没有这两条时，实测一个新练气号 60 秒里六成帧在赶路、每分钟三杀——它总被拉去追
别人已经打了一半的狼。

**BOSS 是号召。** 活着的 BOSS 在 30 格（`ZONE_BOSS_CALL`）内压过所有妖兽，
更远则按 ×0.35 折算距离参与比较：北半张图的修士立刻转向，
七十格外的入口人群照旧刷狼。**号召只叫得动打得过它的人**——`stageIndex ≥ BOSS 阶 − 2`
（`ZONE_BOSS_CALL_STAGES`）才把 BOSS 纳入比较，低于门槛的完全无视它（被它打了照旧反击）；
否则入口的狼一被占满，练气·前期的新号就会照着折算距离走七十格去送死（实测 216/249 帧在赶路、零杀）。
BOSS 被拉出巢穴后和别的妖兽一样走回去，
但**不回血、不清伤害账**——它靠一小股从南边走上来的修士慢慢磨，
每次归位就满血的话谁也杀不掉（实测一次要 430 秒、满血三次）。

**收益为什么打折。** 击杀沿用 §8 的奖励与掉落表，但乘 `zoneRewardScale`（默认 0.3），
离线属主再乘 `zoneOfflineYield`（默认 0.5），**BOSS 不打折**。
理由是算出来的：自动战斗每 10–15 秒一杀，而一只妖兽给「1.5 分钟挂机」，
不打折就是挂机修炼的 **6–9 倍**，直接击穿本节「活跃 ≈ 3 倍挂机」的设计。
0.3 让它落回 2–3 倍——地图仍是最划算的主动玩法，但不至于让其余玩法失去意义。
修炼懒结算照旧，与角色站在哪里无关。

**离线留场。** 属主下线后角色留在图里继续刷，到 `lastSeenAt + offlineCapHours` 自动离场；
**离线玩家不可被任何修士攻击**，被妖兽杀死也无损失。回来在「闭关归来」里看到这段时间的击杀与掉落。
所以地图不需要第二个离线上限旋钮——它复用 `offlineCapHours`，只多一个 `zoneOfflineYield` 折价。

**妖兽供给是这张图真正的旋钮。** 一个找不到近处妖兽的修士会走去全图最近的那一只——
`pickBeast` 不设视野上限——所以妖兽比人少的图会退化成所有人追着同几只跑。
每张图因此按 `(机器人上限 + 8 名玩家) ÷ 12 秒` 算需求，再把刷新吞吐
（`Σ count ÷ respawnSec`，`zoneSpawnThroughput`）配到需求的三倍上下：
入口两侧的低阶妖兽是全图最密、复活最快的一档（5–6 秒），越往北越少越慢。
四张图各 73–76 只，其中入口带占三分之二。

**入口带按解锁阶配。** 入口两侧那两组妖兽的 `stageIndex` = 该图 `unlockStage`
（青云狼 0、水匪 4、灯鬼 8、冰麒麟 12），往北那两组 = `unlockStage + 2`，BOSS 不动。
理由是刚进门的人就是解锁阶那一档：青云狼原本 1 阶，练气·前期跟它是同辈——
四百次单挑输 8 次，中位 9 次出手、只剩三成五气血，两只就得躺一次；
落到 0 阶后四百战全胜，中位 8 次出手、剩六成四气血，一分钟四到六杀而一次不死。
往北仍然更硬——难度曲线还是「走多远」。

**机器人同图。** 机器人在活跃时段的 `explore` 分支进图（按 `zoneFor(stageIndex)` 选图，
两成掷到高一档），驻留满 10 分钟后若转为修炼则一半机会离图，非活跃时段必离。
它们最多占 `capacity × 0.3`（120 里的 36 个，`ZONE_BOT_SHARE`），且不进到
`capacity − 20` 以内——前者保证妖兽不被机器人吃光，后者保证位置永远留给玩家。
被挡下的机器人回去修炼，下一息再试。同样刷怪、同样得修为——
和其余系统一样，机器人不开小灶。

**图内互斗（`mapPvp`，默认关）。** 开启后机器人按 `aggression` 攻击境界 ±4 阶、在线、
不在保护期的玩家，杀死搜走 `mapPvpStoneLoss`（默认 5%）的灵石；玩家只反击。
关闭时当场清空所有修士对修士的目标。

## 10. 机器人修仙者

**核心设计：机器人不是特例。** 它们是 `isBot: true` 的普通 `CharacterState`，
走完全相同的 `settleCultivation`、`attemptBreakthrough`、`computeStats`、`simulateBattle`。
差别只在一个 `BotParams` 参数块——所以机器人的战力和玩家的战力是同一个意思，
榜单可比，PK 公平。

```ts
BotParams = {
  talent: number         // 修炼速率乘数
  diligence: number      // 活跃时段内真正用于修炼的比例
  insight: number        // 突破成功率加成（也进修炼速率）
  aggression: number     // 每 tick 选择 PvP 行为的概率
  activeHours: [start, end]   // UTC 小时，可跨午夜；end 可为 24
  explorePref: 'cultivate' | 'explore' | 'dungeon' | 'arena'
}
```

| 原型 | talent | diligence | insight | aggression | 活跃 | 偏好 | 人口权重 |
|---|---:|---:|---:|---:|---|---|---:|
| 天骄 | 2.5 | 0.9 | +0.15 | 0.3 | 8–24 | 副本 | 6 |
| 苦修 | 1.0 | 1.0 | 0 | 0.1 | 全天 | 修炼 | 22 |
| 散修 | 0.8 | 0.5 | 0 | 0.2 | 6–22 | 探索 | 34 |
| 纨绔 | 1.5 | 0.3 | 0 | 0.4 | 12–4 | 论道 | 18 |
| 魔修 | 1.2 | 0.7 | +0.05 | 0.8 | 18–6 | 论道 | 12 |
| 隐士 | 1.0 | 0.6 | +0.10 | 0 | 4–10 | 修炼 | 8 |

权重让世界以散修和苦修为主，天骄稀少（榜首才有含金量），魔修构成 PvP 压力源。
活跃时段错开，世界任何时候都有人在动。非活跃时段速率 ×0.25。

```
机器人修炼倍率 = talent × (1 + insight) × (活跃 ? 1 : 0.25) × diligence
```

天骄满速 2.875 倍、散修 0.4 倍——**7 倍差距**，一个月后境界分布会自然拉开，
榜单看起来像真实社群而不是整齐的等差数列。

**行为决策** `decideBotAction`：圆满时永远优先突破（这就是世界频道
`system:notice` 突破播报的来源），否则按 diligence 决定是否只修炼，
再按 aggression 掷是否找人 PK，最后落到 `explorePref`。

**装备**：机器人不持有背包行，四个槽位存的是合成 uid `bot:<itemId>`，
由 `(机器人 id, 大境界, BotParams)` 推导（`engine/bots/gear.ts`），
`resolveEquipment` 认得这个前缀——论道、围攻、公开档案、排行榜因此拿到的
都是同一套带装备属性，各模块不必为机器人开分支。

- **谁填得满**：家底 = 0.34 × 天赋 + 0.30 × diligence + 0.36 × 机缘。
  机缘是按机器人 id 播种的终身一掷，同原型的两个人也因此不同。
- **谁品阶高**：talent 越高越可能拿到当前境界能用的最新一档；
  每人最多一件「最新档」，没有人四格全顶配。
- **随境界升级**：种子含大境界，跨大境界即重掷；且新一档要等境界超出
  `requiredStage` 两阶才进入候选（`GEAR_LAG_STAGES = 2`），
  免得圣阶法宝刚解锁那一阶就顶半身战力。
- **幂等**：推导是纯函数，引擎 `start()` 调 `ensureGear()` 把槽位回写一遍，
  旧世界的机器人不需要迁移就能补齐，第二遍写 0 行。

同阶方差（200 机器人实测，`powerScore` / 裸基线）：最低 1.03×、中位 1.22×、
最高 1.39×；每个境界上天骄的中位数都高于散修。装备只做加法，1.0× 是下限。

**道号生成器** `generateBotName(seed)`：姓（含南宫/欧阳/司徒等复姓）+ 1–2 个字 +
50% 概率的道号尾缀（子/真人/散人/老祖…），seed 可控、可复现。
`generateBotNames(seed, n)` 批量去重生成。

后台可：按原型批量生成（指定境界区间与随机种子）、逐个改参数/境界、删除、
改原型模板（影响后续生成）。

## 11. PvP 与社交

- **组队**：6 位邀请码，最多 4 人（`world.maxPartySize`），共同下副本、共享掉落。
- **论道（Arena）**：同境界附近匹配，每日 10 次（`world.arenaDailyLimit`），
  ELO 式 `arenaRating`（初始 1000）。对手可以是玩家也可以是机器人。
  战斗全程用同一个引擎，结果存回放。
- **围攻（Raid）**：组队打机器人。机器人有血池与 `protectedUntil` 保护期
  （`world.raidRecoverMinutes`，默认 30 分钟），打空才算击破并瓜分赏金。
  多波攻击累计，所以真正的强敌需要多人多次。
- **声望**：只从围攻击杀来。击破一个目标，在场每人各得
  `(stageIndex + 1) × 10`——按目标境界给，且是每人一份而非瓜分，
  所以人多不吃亏。记在 `CharacterState.prestige`，己身页显示。
- **好友**：申请/接受/删除，在线状态实时推送。
- **聊天**：世界频道 + 队伍频道，系统频道播报突破、BOSS 击杀、公告。
  两个频道都落库：队伍消息按 `party_id` 存取，刷新后仍在，且只回给本队。

| `monsterDensity` | 1 | 每个刷新点的妖兽数量倍率 |
| `respawnMultiplier` | 1 | 妖兽复活间隔倍率 |
| `bossIntervalMinutes` | 30 | BOSS 现身间隔（分钟） |
| `mapPvp` | false | 图内修士能否互相攻击 |
| `mapPvpStoneLoss` | 0.05 | 被修士击杀时被搜走的灵石比例 |
| `mapDeathRespawnSec` | 10 | 阵亡后回入口复活的等待秒数 |
| `zoneRewardScale` | 0.3 | 地图击杀的收益折扣（BOSS 不打折） |
| `zoneOfflineYield` | 0.5 | 离线属主留场时的收益再乘数 |

> `WorldSettingsPatchSchema` 是**真正的部分更新**——字段上刻意不写 zod `.default()`，
> 默认值单独放在 `DEFAULT_WORLD_SETTINGS`。否则一次只改 `botCount` 的 PUT 会把
> 其余 26 项静默重置为默认值。加载存量配置用 `hydrateWorldSettings(stored)`。

## 13. 数值取舍备忘

写给后续调参的人：

1. **节奏与数字解耦**。想让游戏整体变快，只改 `REALM_BASE_SEC`；
   想让修为数字更好看，只改 `REALM_RATE`。两者互不影响。
2. **奖励用时间表达**。怪物给多少修为不是拍脑袋，是「相当于挂机多久」。
   这让奖励在 36 个阶上自动成立。
3. **圆满是墙，前期是奖励**。境界交界处时长下降是刻意的正反馈。
4. **95% 突破上限**永远保留失败可能，是修仙题材的情绪核心。
5. **atk²/(atk+def)** 而不是减法，让防御永远有用但永远不能免疫。
6. **机器人共用全部公式**是最重要的一条。任何「给机器人开小灶」的改动都会
   让榜单失去意义，请优先调 `BotParams`。
7. **同类加成相加不连乘**，玩家能心算，策划能预测。
8. **自动战斗必须打折**。第 2 条把奖励钉在「相当于挂机多久」上，于是任何**不需要点击**的
   产出都会按它的杀怪频率自动放大——战斗大地图每 10–15 秒一杀，就是 6–9 倍。
   `zoneRewardScale` 是这条通道上唯一的闸；此后每加一个自动玩法，都要先算出它的倍数、
   再决定折扣，而不是等经济崩了再回收。
